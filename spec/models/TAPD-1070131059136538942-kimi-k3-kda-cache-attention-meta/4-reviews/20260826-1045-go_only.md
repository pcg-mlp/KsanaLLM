## C. P1 应改项
- `csrc/layers/nvidia/kda_attention_layer_test.cpp:119` — cu_seqlens ABI 迁移未完成：层读 uint64，层级测试仍上传 int32
  - 证据：
    - 本 commit 把 `csrc/layers/nvidia/kda_attention_layer.cpp` 改为读 uint64：
      ```cpp
      // kda_attention_layer.cpp:70 (RunPrefillConv)
      conv.cu_seqlens = inputs.cu_seqlens->GetPtr<uint64_t>();
      // kda_attention_layer.cpp:119 (RunPrefillCore)
      chunk.cu_seqlens = inputs.cu_seqlens->GetPtr<uint64_t>();
      ```
    - `kda_kernel_wrapper_test.cpp` 同步迁到 uint64（`Upload<uint64_t>` / `As<uint64_t>`，本 commit 已改）。
    - 但 `kda_attention_layer_test.cpp` 未在本 commit 触及（`git log` 显示最后修改为旧 MR `401c9593`），仍：
      ```cpp
      // kda_attention_layer_test.cpp:119
      Tensor cu_seqlens = UploadTensor<int32_t>(DataType::TYPE_INT32, {2}, {0, 1});
      // ...
      inputs.cu_seqlens = &cu_seqlens;  // 8 字节（2×int32）
      ```
    - `PrefillLaunches` 经 `layer_.ForwardPrefill` → `RunPrefillConv` 把该 int32 缓冲按 `uint64_t*` 读：`cu_seqlens[0]` 被解释为 `{0,1}` 两个 int32 拼成的一个 uint64（小端 = 0x0000000100000000 = 4294967296），`cu_seqlens[1]` 越界读缓冲外 8 字节。该测试只断言 `.OK()` + `cudaSuccess` + 输出 shape，不校验数值——很可能**假绿**掩盖真实 ABI。
  - 旁证（潜伏，未触发）：`csrc/models/kimi_k3/attention_meta/kimi_k3_attention_meta_creator.cpp` `CreateFlashAttentionMeta` 仍把 `cu_seqlens_tensor` 建为 `TYPE_INT32` 并由 `PrepareChunkKDA` 填 `int32` 主机数据；按命名预期它将接入 `KdaPrefillInputs.cu_seqlens`，届时与层的 uint64 读再次不一致。当前 `KimiK3DecoderLayer::CommonAttn` 对 KDA 层 `return Status()`（stub，KDA forward 未接），故 KimiK3 路径未触发。
  - 建议：补全迁移——`kda_attention_layer_test.cpp` 的 `cu_seqlens` 改 `UploadTensor<uint64_t>(TYPE_??, {2}, {0,1})`（注意需有对应 uint64 dtype 常量，或用 BYTES/int64 容器承载）；`kimi_k3_attention_meta_creator.cpp` 的 `cu_seqlens_tensor` 与 `PrepareChunkKDA` 的 `cu_seqlens_host` / `MemcpyAsync` sizeof 一并改 uint64。回 `ai-go` 修复。

## D. P2 建议项
- `csrc/models/kimi_k3/kimi_k3_model.cpp` CommonAttn（约 `kimi_k3_model.cpp:126`） — KDA 层静默 no-op：`mla_` 为空时 `CommonAttn` 直接 `return Status()`，hidden state 原样穿过、无日志无断言。若 KDA 层在生产路径误激活会静默降质。建议 KDA 分支加 `KLLM_LOG_WARNING`（once）或显式 `TODO/KLLM_CHECK` stub 标记，避免「成功但没算」。
- `csrc/models/kimi_k3/attention_meta/kimi_k3_attention_meta_builder.cpp` `InitMambaBasePointersIfNeeded`（约 `:18-44`） — `layer_mamba_kv_cache_ptr_tensor` 声明 dtype=INT64，但同一缓冲既以 `GetPtr<int64_t>()` 写偏移、又以 `GetPtr<void*>() + 1` 改写为绝对指针并读，属 strict-aliasing 邻域 UB（LP64 下 int64/void* 均 8 字节可工作，但语义上 INT64 张量存指针不对）。建议：统一以 `int64_t`/`uintptr_t` 存偏移、在使用点解析为指针，或拆成「偏移表」与「指针表」两个张量。
- `csrc/cache_manager/cache_layout/kda_cache_layout.h` GetKvCacheLayerOffsets（约 `:40-50`） — 非 KDA 层返回 `{0,0}` 而非哨兵；offset 0 同时是 layer-0 conv_state 基址，若访问点漏掉 `IsKdaLayer` 守卫会静默读写 layer-0 状态。`InactiveLayerGetsZeroOffset` 测试断言 0（by design）。建议文档化「offset 0 ≠ no-state，必须由 IsKdaLayer 守卫」，或改用 `SIZE_MAX` 哨兵。
