## C. P1 应改项

- `csrc/modules/basic/flash_attention.cpp:126` — `decode_token_num` 取 `fs.shape[12]`，对 flexible shape 布局是隐式下标耦合
  - 证据：注释自证"shape[12] (dp_decode_tokens)…matches qkv->shape[0]"，但该下标协议无编译期断言保护；shape 布局演进时此处会静默取错值（取到别的 token 计数字段而不报错）。
  - 建议：在 shape 构造侧（meta 定义处）加命名常量或 static_assert 注释对索引，或在 `FlashAttention::Forward` 加一次 `decode_token_num <= qkv->shape[0]` 的廉价 CHECK。

- `csrc/layers/nvidia/fp8_moe_layer.cpp:92` — bias 来源从 `eplb_map` 改读 `e_score_bias` 属于行为修正，需确认调用方在所有 fp8 MoE 配置下都传了 `e_score_bias`
  - 证据：新逻辑 `use_e_score_correction_bias && e_score_bias != nullptr` 时才取指针——当 config 声明 `use_e_score_correction_bias=true` 但上层传 `nullptr` 时静默退化为无 bias（旧逻辑会拿 `eplb_map` 顶包，虽然语义是错的但至少有值）。
  - 建议：对"use_e_score_correction_bias=true 但 e_score_bias==nullptr"的组合加 CHECK 或 LOG_WARNING，避免配置与接线不一致时静默丢 bias。
